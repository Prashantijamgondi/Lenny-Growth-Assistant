# Architecture Specification: The Lenny Growth Assistant

## 1. System Topology
The system is orchestrated using Docker Compose and consists of three main containers:
- **Frontend (Next.js):** Serves the UI, manages chat state, and handles the sandboxed artifact viewer.
- **Backend (FastAPI):** Exposes REST/SSE endpoints, manages database sessions, executes vector search, and routes LLM calls.
- **Database (PostgreSQL + pgvector):** Stores session metadata, message history, generated artifacts, and the transcript vector embeddings.
- *(Optional)* **Ollama:** A local daemon running on the host machine (or in a container) providing inference for the `llama3.2:3b` or `llama3.1:8b` models.

## 2. Component Boundaries
### Frontend Layer
- Uses React Server Components (Next.js App Router) where possible, with Client Components for the interactive chat and artifact streaming.
- Communicates with the Backend via standard HTTP POST for session creation and Server-Sent Events (SSE) for streaming model responses.

### Backend API Layer
- **`/api/sessions`**: CRUD for chat sessions.
- **`/api/chat`**: Streaming endpoint (SSE) that handles incoming messages, performs RAG, and interfaces with the LLM provider.
- **`/api/health`**: Healthcheck endpoint to verify database and LLM provider connectivity.

### Provider Abstraction
- The LLM logic is abstracted behind a `BaseLLMProvider` interface.
- `OllamaProvider` connects via `httpx` to the local Ollama API.
- `CloudProvider` (e.g., Anthropic) uses their respective SDKs or HTTP endpoints.
- A factory pattern decides which provider to instantiate based on the incoming request header or `.env` configuration.

## 3. Data Schema (PostgreSQL)

```sql
-- Enables vector extension
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(255),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id UUID REFERENCES sessions(id) ON DELETE CASCADE,
    role VARCHAR(50) NOT NULL, -- 'user', 'assistant', 'system'
    content TEXT NOT NULL,
    sources JSONB, -- Array of cited transcript references
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE artifacts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    message_id UUID REFERENCES messages(id) ON DELETE CASCADE,
    artifact_type VARCHAR(50), -- 'markdown', 'html'
    title VARCHAR(255),
    content TEXT NOT NULL
);

CREATE TABLE transcript_chunks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    episode_title VARCHAR(255),
    guest_name VARCHAR(255),
    chunk_text TEXT NOT NULL,
    timestamp_ref VARCHAR(50),
    embedding vector(384) -- Using all-MiniLM-L6-v2 dimensions
);

-- HNSW index for fast approximate nearest neighbor search
CREATE INDEX ON transcript_chunks USING hnsw (embedding vector_cosine_ops);
```

## 4. Ingestion & Retrieval Flow
1. **Ingestion:** `scripts/ingest.py` reads local Markdown/TXT files, splits text using a recursive character chunker (approx. 500-800 tokens, 100 overlap).
2. **Embedding:** `sentence-transformers/all-MiniLM-L6-v2` encodes the text into 384-dimensional vectors.
3. **Storage:** Vectors and metadata are inserted into `transcript_chunks`.
4. **Retrieval:** On user query, the query is embedded, and a SQL query calculates the `vector_cosine_ops` against the HNSW index to return the top 5 most similar chunks.

## 5. Security & Artifact Sandboxing
- **Backend:** Input validation via Pydantic models. SQL injection prevented by SQLAlchemy ORM/parameterized queries.
- **Frontend Artifact Viewer:**
  - Content generated by the LLM is explicitly marked untrusted.
  - HTML strings are sanitized using `DOMPurify`.
  - The sanitized HTML is injected via `srcDoc` into an `iframe`.
  - The `iframe` is restricted with `sandbox="allow-scripts"`. By omitting `allow-same-origin`, the browser forces the iframe into a unique origin, blocking it from accessing the parent window's `localStorage`, `cookies`, or DOM.
